# weather-digest

Консольная утилита «Погодный дайджест». По названию города (или списку городов
через запятую) получает координаты и прогноз погоды через открытый API
Open-Meteo, выводит результат в терминал и сохраняет отчёт в файл.

## Требования к окружению

- Node.js версии 20 и выше (используется встроенный `fetch`).
- Доступ в интернет к `geocoding-api.open-meteo.com` и `api.open-meteo.com`.

## Установка

```bash
git clone https://github.com/oxolegit/weather-digest.git
cd weather-digest
npm install
cp .env.example .env
```

Сторонних зависимостей для запуска утилиты не требуется — `npm install`
нужен только для dev-инструментов (тесты, линтер), если планируется их запускать.

## Переменные окружения

| Переменная           | Назначение                                   | Значение по умолчанию                            |
| -------------------- | -------------------------------------------- | ------------------------------------------------ |
| `GEOCODING_API_URL`  | URL API геокодинга                           | `https://geocoding-api.open-meteo.com/v1/search` |
| `FORECAST_API_URL`   | URL API прогноза погоды                      | `https://api.open-meteo.com/v1/forecast`         |
| `REQUEST_TIMEOUT_MS` | Таймаут одного HTTP-запроса, мс              | `5000`                                           |
| `REPORTS_DIR`        | Каталог для сохранения отчётов               | `reports`                                        |
| `TEMPERATURE_UNIT`   | Единица измерения температуры (информативно) | `celsius`                                        |
| `PRECIPITATION_UNIT` | Единица измерения осадков (информативно)     | `mm`                                             |

Файл `.env.example` содержит пример со значениями по умолчанию. Файл `.env`
в репозиторий не попадает.

## Запуск

```bash
node src/index.js --city "Нижний Новгород" --days 3
node src/index.js --city "Москва,Казань,Сочи" --days 5
node src/index.js --city "Москва" --no-cache
node src/index.js --help
```

Параметры:

- `--city`, `-c` — название города или список городов через запятую. Обязательный параметр.
- `--days`, `-d` — количество дней прогноза, целое число от 1 до 7. По умолчанию `3`.
- `--no-cache` — не использовать сохранённый на сегодня отчёт, выполнить запрос заново.
- `--help`, `-h` — показать справку.

Через npm-скрипт:

```bash
npm start -- --city "Нижний Новгород" --days 3
```

## Пример вывода

```
Москва, Россия
Координаты: 55.75204, 37.61781
Дата        Мин, °C   Макс, °C   Осадки, мм
2026-09-13     7.7        16.2            0
2026-09-14     9.2        18.4            0
2026-09-15    11.7        18.6          0.1
```

При повторном запуске за тот же день рядом с названием города выводится
пометка `(из кэша)`, и сетевые запросы не выполняются.

## Кэширование

Отчёт по каждому городу сохраняется в файл `reports/{город}-{ГГГГ-ММ-ДД}.json`.
При повторном запуске в тот же день утилита читает данные из файла и не
обращается к сети. Флаг `--no-cache` принудительно выполняет запрос заново
и перезаписывает файл отчёта.

## Обрабатываемые ошибки

- Отсутствующий или некорректный аргумент (`--city` не указан, `--days` вне диапазона 1–7).
- Город не найден (пустой результат геокодинга).
- Ответ API со статусом 4xx — сообщение об ошибке в запросе.
- Ответ API со статусом 5xx — сообщение о временной недоступности сервиса.
- Отсутствие сети.
- Превышение таймаута запроса.
- Некорректный JSON в ответе API.

Ошибки выводятся понятным сообщением на русском языке, без стек-трейса.
Города обрабатываются параллельно: ошибка по одному городу не прерывает
обработку остальных.

**Код завершения процесса:** `0` — все города обработаны успешно,
`1` — ошибка аргументов или сбой хотя бы по одному городу.

## Структура проекта

```
src/
  index.js            точка входа: разбор аргументов, запуск, код завершения
  config.js           настройки из переменных окружения
  errors.js           классы ошибок приложения
  cli/args.js         разбор и валидация аргументов командной строки
  api/http.js         обёртка над fetch: таймаут, обработка HTTP- и сетевых ошибок
  api/openMeteo.js     запросы геокодинга и прогноза Open-Meteo
  services/weather.js  бизнес-логика: получение прогноза, кэш, обработка списка городов
  storage/reports.js   чтение и запись отчётов в reports/
  format/console.js    вывод прогноза в консоль
tests/                 тесты (node:test)
docs/postman/          коллекция Postman
docs/report.html       страница для просмотра сохранённого отчёта в браузере
```
